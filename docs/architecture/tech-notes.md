# 《后室：无尽回廊》技术要点（Tech Notes）

> 版本：v0.2 ｜ 状态：草案（M0 原型直接验证 §1/§2/§5）｜ 依据：`docs/gdd-v0.2.md` §6.2-§6.4、`docs/design-review.md` P0-6/P1-1/P2-3
> 范围：确定性生成、世界持久化、流式加载与渲染、程序化音频、生成内容 QA 与 Telemetry、性能预算。

## 1. 确定性生成

### 1.1 目标

同一 `(层级ID, 种子)` 永远生成同一层级——"回到 Level 1 的家"叙事成立的前提，也是世界持久化（§2）的地基。

### 1.2 PRNG：mulberry32

```
function mulberry32(seed) {
  let a = seed >>> 0;
  return function() {
    a |= 0; a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

- 32 位种子、实现 <10 行、跨平台可复现；全部随机决策走**同一 PRNG 流**，禁止原生 rand / `FRandomStream` 之外的随机源。

### 1.3 种子派生：hashString

- `种子 = hashString(层级ID) ^ 轮次种子`（建议 FNV-1a 32bit 或 UE 稳定实现），层级 ID 混入避免"Level 0 / 0.1 / -1"布局雷同。

| 输入 | 决定 |
|------|------|
| `levelId` | 层级身份（hashString 混入） |
| `seed`（轮次种子） | 同一层级不同轮次的布局差异 |
| 生成器版本号 | 算法升级时旧存档的迁移依据（§2.3） |

### 1.4 确定性纪律

1. 生成器只依赖输入三元组，禁止时间/线程序/全局状态。
2. L2 的 PCG 采样顺序锁定（同输入同输出），必要时做确定性封装。
3. 算法变更递增 `layoutVersion` 写入存档；版本不一致走 delta 迁移（§2.3）。

## 2. 世界持久化

### 2.1 核心模型：`(层级ID, 种子, delta)` 三元组

```
存档条目 = { levelId: "level-1", seed: 0x8F3A21C7, delta: [ ...玩家修改记录 ] }
```

- **基线 = 确定性生成结果**：重启后重算，无需序列化整个关卡。
- **delta 只存修改**：取走的物品、写下的字、移动的物体、陈列摆放、激活的机关。

### 2.2 delta 记录设计

| delta 类型 | 内容 | 示例 |
|-----------|------|------|
| `item.taken` | 物品实例 id | 杏仁水@room-7 已取走 |
| `item.moved` | 实例 id + 坐标/朝向 | 椅子@corr-3 位移 |
| `world.text` | 玩家书写文本 + 位置 | "我在这里活过"@wall-12 |
| `trap.triggered` | 一次性机关状态 | 电梯@anchor-2 已激活 |
| `exhibit.place` | 陈列室摆放 | 空瓶→架位 3 |

- 上限 256 条/层，超限按 FIFO 淘汰（物品类 > 文字类 > 位置类）；基地（陈列室）数据单独存档，与 Codex 同层跨轮持久。

### 2.3 存档结构建议

```
SaveData
├── meta:      { saveVersion, layoutVersion, 游玩时长 }
├── run:       { 三态/位置/当前层, 存活回合 }          // 随角色，死亡重置
├── codex:     { 已发现层级, 文档, 图鉴, 笔记, 死亡记录 } // 跨轮持久
├── world:     [ { levelId, seed, delta[] } × N ]     // 已访问层级状态
└── exhibits:  [ { shelfId, itemId, 摆放 } ]           // 陈列室独立存档
```

- Codex 与角色存档分离（GDD §3.6）：角色死亡只清 `run`；存档体积目标单档 < 2MB，未访问层只留元数据。

## 3. 流式加载与实例化渲染

| 技术 | 用途 | 约束 |
|------|------|------|
| 分层加载 | 仅加载当前层级，层间切换走流式关卡 | 同屏最多 1 层 + 出口预载区域 |
| ISM（Instanced Static Mesh） | 地板/墙/顶/家具重复资产合并实例 | 单资产单材质实例化 |
| LOD（3 级） | 远距离降面 | 按 §6 预算表 |
| Nanite | A 类高面数 set piece 资产 | 按资产验收清单启用 |
| 动态卸载 | 离开区域即卸载实例 + 材质流送 | 内存预算 §6 |

- **实例化纪律**：资产库按材质分组（atlas 贴图），同房间尽量单材质集，DrawCall 预算见 §6。
- 非欧/循环空间（`looping`）用"传送式可见性切换"实现，不依赖物理世界坐标统一。

## 4. 程序化音频

后室恐怖 70% 靠声音，而 1 名音频设计师无法手作数千层级音频——走系统生成。

```
环境底噪（DNA soundscape.ambient，循环）→ 突发音效（soundscape.startles 池，随机容器）→ 音乐（仅安全层/特殊事件）
```

| 技术 | 做法 |
|------|------|
| Wwise 随机容器 | 底噪/突发音效用 Random Container + Sequence，种子化排列与层级种子挂钩，保证可复现 |
| 底噪合成 | 灯管嗡鸣=正弦 50Hz+100Hz 叠加 + 轻微 FM；风/远方脚步=滤波噪声合成；参数来自 DNA `soundscape` |
| audio ducking 静默切层 | `silenceEvents=true` 时按概率瞬间压低底噪至 -30dB 并停用突发层——"突然的寂静"是最便宜的恐怖手段 |
| 理智联动 | Sanity<30 叠加音高漂移 + 相位失真 + 假脚步声（幻觉层，与视觉幻觉同步） |
| 3D 空间音频 | 脚步方向感、墙后刮擦声：UE 音频遮挡 + 反射，实体声源 3D 定位 |

- 音频设计产出"参数配方"而非逐条音效；Wwise 工程版本化进 Perforce。

## 5. 生成内容 QA 与 Telemetry

### 5.1 CI 冒烟测试

```
CI Job：1000 种子 × 每个已发布 DNA 模板
  1. 批量无头生成（复用 PCG.Core/Topology/Validation，不进编辑器）
  2. 每层校验：
     - BFS 可达性：出生点 → 非 hidden 出口 / set piece 锚点
     - 实体密度、物品数在 DNA 区间内；无死锁房间
     - 布局 hash 与预期一致（确定性回归）
  3. 失败 → 备用种子重试 ≤8 次 → 仍失败则 BLOCKED 上报
```

- 触发器：DNA 模板/生成器/资产库变更自动全量跑；夜间 1000 种子全量回归。通过线：**0 BLOCKED、重试率 < 5%**，否则阻断合并。

### 5.2 Telemetry 指标

| 指标 | 定义 | 反馈闭环 |
|------|------|---------|
| 层级卡死率 | 玩家在该层 10 分钟无进展/无移动的比例 | 回写 DNA 模板（出口太隐、房间死区） |
| 实体卡墙率 | 实体与碰撞体重叠事件占比 | 回写实体生成参数（密度/巡逻路径） |
| 掉入虚空率 | 玩家坐标越界（掉落）事件占比 | 回写拓扑校验（碰撞缺失/缝隙） |

- 埋点只上报聚合计数 + `(levelId, seed, layoutVersion)`，不采集身份/轨迹（合规，GDD §9）。
- 阈值：单层卡死率 > 8% 或掉虚空率 > 2% → 模板进"待修复"队列，人工复现后修 DNA 或生成器。

## 6. 性能预算表（中端 PC，1080p/60fps，UE5）

| 维度 | 预算 | 说明 |
|------|------|------|
| 三角面（同屏） | ≤ 2,000,000 | Nanite 资产独立预算 |
| DrawCall（同屏） | ≤ 800 | 靠 ISM 合并；材质切换 ≤ 60 次 |
| 材质数（同屏） | ≤ 40 | atlas 贴图集合并 |
| 内存（关卡加载态） | ≤ 1.5GB | 含贴图流送池，超限触发动态卸载 |
| 贴图内存 | ≤ 800MB | 1024px/m texel + mip 流送 |
| 生成耗时（单层） | ≤ 200ms | L1+L2，重试 8 次 ≤ 1.6s |
| 存档写入 | ≤ 100ms | delta 增量写 |
| 音频 | 64 Voice 上限 | Wwise 声部预算池 |

- 每层生成后附性能预估清单（实例数/材质数），超预算模板在 CI 标记；M0 用 3 个 A 类层实测校准，M1 EA 前冻结为硬预算。

## 7. 关键技术决策与风险

| # | 决策 | 理由 |
|---|------|------|
| 1 | 确定性 PRNG 用 mulberry32 | 实现短、可审计、跨平台一致 |
| 2 | 存档存 delta 不存全量关卡 | 体积小、可迁移、与确定性生成解耦 |
| 3 | L2 用 UE5 PCG，L1 自研 | 拓扑/空间规则/出口图需自定义（pcg-architecture §7） |
| 4 | 音频走 Wwise 程序化管线 | 1 人覆盖数千层级（GDD §5.2） |
| 5 | Telemetry 只上报聚合数据 | 合规最小化（GDD §9） |

| 风险 | 对策 |
|------|------|
| UE5 PCG 确定性难保证 | 采样顺序锁定 + 布局 hash 回归（§1.4/§5.1） |
| delta 膨胀 | 容量上限 + FIFO 淘汰 + 稀疏编码（§2.2） |
| 非欧层流式加载穿帮 | 传送式可见性切换 + 预载区域规划（§3） |
| 程序化音频同质化 | 种子化排列 + 静默切层 + 理智联动分层（§4） |
