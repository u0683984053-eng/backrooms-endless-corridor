# 《后室：无尽回廊》程序化生成架构（PCG Architecture）

> 版本：v0.2 ｜ 状态：草案 ｜ 依据：`docs/gdd-v0.2.md` §6.2、`docs/design-review.md` P0-1/P0-2/P0-6、`schemas/level-dna.schema.json`
> 铁律：**程序化只生成"背景板"，恐怖由 set piece（前景异常）负责。**

## 1. 目标与范围

| 目标 | 验收口径 |
|------|---------|
| 规模 | 1.0 时支撑 A(40)+B(250)+C(无限)，全走同一管线 |
| 质量 | 程序化只做"合理、稳定、符合美学"的背景板，异常叙事全部来自 set piece |
| 确定性 | 同一 `(层级ID, 种子)` 永远生成同一层级，支撑世界持久化（GDD §6.3） |
| 可测 | 每个生成结果可被 CI 冒烟测试自动校验（可达性/密度/死锁） |

> 范围边界：本架构覆盖"生成可玩关卡"本身；运行时流式加载见 `tech-notes.md`，资产生产见 `asset-pipeline.md`。

## 2.1 连通性保证策略（可复用算法，proto 已验证）

生成算法按"连通性优先"设计，四个层次（原型 `proto/engine/generator.js` 已实现并通过 180+ 项测试）：

1. **骨架全连通**：`hallwayGrid` 模式（经典 Level 0）用纵横走廊网格作骨架——网格本身无死角；常规模式用「房间 + L 形走廊最小生成树」连接全部房间。
2. **房间挂接**：房间通过可通行的门（`D` 瓦片）挂到骨架上；门按概率散布营造氛围，并有「每区块 ≥1 门」的确定性保底修复。
3. **容差校验**：生成后 BFS 验证——出口必达；连通率目标 **≥98%**（非环绕视角），**游戏内环绕视角 100%**；失败则用备用种子重试（≤8 次，备用序列本身确定）。
4. **确定性纪律**：全部随机取自 `mulberry32(seed)`（`层级ID + 轮次种子` 派生），**绝不使用 `Math.random`**——同种子永远同布局，支撑世界持久化。

> 复用方式：新增 B/C 类层级时，在 DNA 中选 `hallwayGrid: true`（走廊网格）或默认（房间+走廊 MST），设置宽高（网格模式需 8 的倍数）与门密度即可，连通性由算法保证。

## 2. 总体架构：两级生成

```
层级请求 (层级ID + 种子)
  │
  ▼
┌─────────────────────────────────────┐
│ L1 拓扑生成（自定义工具，确定性）      │  房间/走廊图 + 空间规则 + 出口图 + set piece 锚点
└─────────────────────────────────────┘
  │ 输出：LevelGraph（纯数据，无资产引用）
  ▼
┌─────────────────────────────────────┐
│ L2 细节生成（UE5 PCG，半确定性）      │  密度填充 + 实体/物品/光照
└─────────────────────────────────────┘
  │
  ▼
生成后校验（BFS 可达性/密度/死锁）──失败──► 备用种子重试（≤8 次）
  │ 通过
  ▼
输出可玩关卡（可进入、可存档、可流式加载）
```

- **L1 是"作者层"**：DNA 模板、空间规则、出口图、set piece 锚点在此确定；纯数据、可单测。
- **L2 是"填充层"**：按密度把资产撒进 L1 骨架；确定性约束内允许少量噪声，但同种子结果必须一致（§8）。

## 3. L1 拓扑生成

### 3.1 输入与输出

- 输入：层级 DNA（`terrain`/`spaceRules`/`exits`/`setPieces`）+ 种子 seed(uint32)。
- 输出 `LevelGraph`：

```
LevelGraph {
  rooms:     [ { id, rect, 类型(房间/走廊/大堂/危险区), 用途(出生/锚点/出口/普通) } ]
  corridors: [ { a, b, 宽度, 类型(直/折/梯/电梯) } ]
  exits:     [ { 位置, kind(卡出/门/梯/电梯/按钮), 目标层级, hidden, danger } ]
  anchors:   [ { 位置, setPieceId, 朝向, 语义(必经/岔路/深处) } ]
  meta:      { seed, spaceRule 应用记录, 尺寸 }
}
```

### 3.2 生成流程（确定性，逐步）

1. **空间骨架**：按 `terrain.width/height` 生成网格，`roomCount` 个房间分区放置，走廊以最小生成树 + 额外回路连接（保证无孤立区）。
2. **空间规则**：按 `spaceRules` 修改图邻接语义——`looping` 边缘环绕、`non-euclidean` 传送式错位；只改图结构，不改资产选择。
3. **出口锚定**：按 `exits` 放到指定语义位置（出生区附近/深处/隐藏角落）；`hidden` 出口不进入"必须路径"。
4. **set piece 锚点预选**：按 `setPieces[].position`（center/random/far-corner）挑选拓扑关键点（必经走廊尽头、环路分叉、深处）。

## 4. L2 细节生成（UE5 PCG）

L2 在 LevelGraph 的每个房间/走廊上执行密度填充：

| 类别 | 来源 | 放置规则 |
|------|------|---------|
| 装饰模块 | 资产库按 `floorStyle/wallStyle` 过滤 | 贴墙/贴地采样，密度按房间类型 |
| 实体 | `entities[].density` × 房间危险度 | 远离出生区 ≥N 格，禁入 set piece 触发范围 |
| 物品 | `items[]` + `itemDensity` | 高亮位优先，重复率受控 |
| 光照 | `light` + `palette.light` | 灯位按网格放置，`flickering` 加闪烁组件 |

- **碰撞保证**：放置前用空间哈希做冲突检测，冲突丢弃重采（确定性 PRNG，不无限随机）。
- **性能约束**：输出遵守 `tech-notes.md` §6 性能预算表。

## 5. Set Piece 锚定机制

**核心原则：set piece 是手工内容，程序化层只负责"放对位置"。**

```
DNA.setPieces[] ──► 手工资产（set piece 组件库 200+，见 asset-pipeline）
      │
      ▼
L1 锚点预选（拓扑关键点）──► 冲突消解（不重叠、出生区可见性检查）
      │
      ▼
L2 阶段冻结 set piece 周围 N 格填充（禁止装饰物侵入触发范围）
      │
      ▼
运行时绑定：文字触发 / 惊吓事件(sanityEffect) / 日志 note 写入
```

- **1-5 个/层**（DNA `setPieces` 数组约束）：A 类 3-5 个定制，B 类 1-3 个复用组件，C 类 0-1 个。
- **行为契约**：`text`（原创文本）/`sanityEffect`/`note`（写 Codex）由 DNA 自带；生成器只摆放与接线，不做叙事创作。
- **质量铁律**：L1 找不到合格锚点时，宁可整层回退备用种子，也不把 set piece 硬塞进不合理位置。

## 6. 生成管线数据流图（文本）

```
DNA JSON ─► DNA 校验器(schema) ─► 生成请求 { levelId, seed }
                                   │
                                   ▼
                        L1 Topology Generator（确定性）
                                   │ LevelGraph
                                   ▼
              ┌─────── 锚点分配器（set piece 定位）───────┐
              │                                          │
              ▼                                          ▼
    UE5 PCG Graph（L2 密度）                  手工 set piece 场景实例
              │                                          │
              └────────────► 合并器（装配/冻结/接线）◄────┘
                                   │
                                   ▼
                          生成后校验器（BFS/密度/死锁）
                            │ 失败 → 备用种子重试（≤8）
                            │ 通过
                            ▼
                      可玩关卡 + 存档种子
```

## 7. 与 UE5 PCG Framework 的职责划分

| 能力 | UE5 PCG | 自定义工具（BackroomsPCG 插件） |
|------|---------|-------------------------------|
| 密度填充（撒装饰/实例化） | ✅ L2 主体 | 只做约束插件 |
| 房间/走廊图拓扑 | ❌ 不适合 | ✅ L1 图算法（确定性） |
| 空间规则（非欧/循环） | ❌ 需大量 hack | ✅ 图结构语义层 |
| 出口图与可达性 | ❌ | ✅ 出口锚定 + BFS 校验 |
| set piece 锚定 | 部分（PCG 采样点） | ✅ 锚点决策 + 冲突消解 |
| 确定性保证 | 需锁采样顺序与噪声 | ✅ 种子管线 + 布局 hash |

> **结论（与 GDD §6.2 一致）**：UE5 PCG 只做 L2 密度；**拓扑、空间规则、出口图必须自定义工具**——这是质量与规模平衡点的工程落点。M0 原型期以 C++/蓝图混合实现，M1 前收敛为独立插件 `BackroomsPCG`（模块 Core/Topology/Anchoring/Validation/UE5，纯数据进出，CI 可无头运行）。

## 8. 确定性要求

- **公式**：`布局 = F(levelId, seed)`；`seed` 为 uint32，`levelId` 经 hashString 混入，杜绝"Level 0 与 Level 0.1 布局雷同"。
- **PRNG**：统一 `mulberry32`（32 位种子、可复现、实现 10 行内），全部随机决策走 PRNG 流，禁止原生 rand。
- **约束**：L2 的 PCG 采样必须锁定采样顺序（同输入同输出）；算法变更时递增 `layoutVersion` 并写入存档（见 `tech-notes.md` §2）。
- **校验**：生成结果附带布局 hash，存档/读档时校验；不一致触发"重生成 + 玩家 delta 迁移"警告。

## 9. 备用种子重试策略

1. 第 1 次使用请求种子 `seed`；失败后使用 `seed + k`（k=1..8），k 由 hashString(levelId+失败原因) 偏移，避免同类层同时撞车。
2. **最多 8 次**；8 次全失败 → 该层标记 `BLOCKED`，走人工排查（CI 报错 + Telemetry 上报），不静默降级生成。
3. 重试代价预算：单次 L1+L2 目标 < 200ms（原型机），8 次 < 1.6s，可接受。

| 校验项 | 失败触发重试 |
|--------|-------------|
| BFS 可达性（出生点→全部关键出口） | ✅ |
| 实体密度/数量越界 | ✅ |
| set piece 锚点冲突未消解 | ✅ |
| 布局 hash 与预期不符（回归） | ✅ |

## 10. 生成后校验与 CI 集成

- **可达性**：从出生点 BFS，必须可达全部非 hidden 出口、全部 set piece 锚点与安全区；hidden 出口单独校验"可达但需搜索"。
- **密度**：实体总数、每房间实体数、物品数落在 DNA 声明区间（`density` × 面积 ± 容差）。
- **死锁**：无玩家不可达的"死房间"（除 DNA 显式声明的无出口陷阱层）。
- **CI**：`1000 种子 × 每层级` 批量无头生成，全量跑上述校验（见 `tech-notes.md` §5）。

## 11. 与三层内容模型的对应及风险

| 内容类 | 生成方式 | L1 定制度 | set piece |
|--------|---------|-----------|-----------|
| A 手工核心层 | 手工拓扑 + 手工 set piece，管线只装配 | 全定制 | 3-5 个定制组件 |
| B 策展生成层 | 手工调优 DNA 模板 × 管线生成 + 人工抽查 | 高 | 1-3 个复用组件 |
| C 野性生成层 | DNA 模板自动变异（参数抖动） | 低 | 0-1 个 |

| 风险 | 对策 |
|------|------|
| PCG 填充千篇一律 | set piece 铁律 + B 类人工抽查 + 月度策展挑选 |
| 非欧几何在 UE5 落地难 | M0 只验证 `looping`，`non-euclidean` 后置单独立项 |
| 布局版本升级破坏旧档 | 布局 hash + 版本号 + delta 迁移（`tech-notes.md` §2） |
| 生成耗时超预算 | 重试预算（§9）+ L2 并行烘焙（M1 起） |

## 12. 无限世界：Minecraft 式分块生成（v0.3 已落地原型）

**动机（F 版保真）**：多数层级（Level 0 黄色迷宫、Level 11 无尽城市等）在设定上"没有边界"——有限地图 + 边缘虚空非常出戏。原型把这类层级改为无边界分块世界，走到哪里生成到哪里；少数有限层级（枢纽、! 跑道、0.1 环面教学层等）保留边界，且边界一律是**墙**而非虚空。

**核心设计**：
- `CHUNK = 16`，chunk 种子 `mulberry32(hash(runSeed|dna.id|cx,cy))`——同一 (层级,种子) 的 chunk 内容永远一致，支持存档重放（序列化只记 `takenItems/deadEntities/chunkKeys`，瓦片全部确定性重建）。
- **网格类拓扑**（hallway-grid / city-grid / hotel / warehouse）用**全局坐标公式**判定走廊/街道/柱列：chunk 边界只是公式的切片，两侧永远无缝对齐；门位由**街区种子**（`blk:bx,by`）决定，与 chunk 无关，跨 chunk 一致。
- **迷宫/洞穴类**（rooms / caves）用**固定边缘端口**：每边 2 个 2×2 开口（局部 (4,0)(11,0) 等），相邻 chunk 端口严格对齐；chunk 内 8 端口 + 1-3 个随机房间 + 顺序 L 走廊全连通。
- **实体/物品**按 DNA 密度在 chunk 内确定性生成，玩家周围 3×3 chunk 激活（稳定 id `"cx,cy:idx"`），取走/击杀记录在 level 集合，跨 chunk 重激活不复活、不重生。
- **出口**：出生点 (0,0) 附近 8-24 格确定性放置 2-4 个（hidden 按 DNA）。
- **有限层墙边界**：统一 `tileAt(level,x,y)`——无限层走 getTile（惰性生成），有限层越界返回 `#`。引擎/CLI/Web 三层全部经由此函数取瓦片，杜绝任何"地图外虚空"。

**测试**（proto/test.js §5.5 等）：端口跨 chunk 对齐、负坐标/远方坐标可生成、同种子 chunk 一致、不同种子不同、无限漫游 60 步不越界、有限层边界挡路、序列化往返，全量 565 项通过。
